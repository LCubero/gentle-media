# Contexto para piezas de medios

**Fuentes:** las referencias con SHA siguientes son fotografías históricas de revisiones concretas (consulta original: 2026-09-27), no verificación del producto actual. La ampliación del showreel se apoya también en el README de Pi instalado localmente y en referencias oficiales móviles de Gentle Shell, indicadas abajo. Este documento orienta piezas creativas; no certifica instalaciones ni versiones publicadas.

## Qué representa cada nombre

- **Gentleman Programming**: úsese como etiqueta del ecosistema en la narrativa de medios, no como afirmación sobre una entidad legal, estructura corporativa o instalación conjunta. Los repositorios describen productos distintos: [Gentle-AI](https://github.com/Gentleman-Programming/gentle-ai/blob/e8c9f5959cda64d64cb375de04fed524fef23d78/README.md), [gentle-shell](https://github.com/Gentleman-Programming/gentle-shell/blob/4f5ab3973dccae74fc981531cd2e8ab8d3c6e8cf/README.md) y [Engram](https://github.com/Gentleman-Programming/engram/blob/9dad41baf01c6b9dacfd13808d614987c787ebc7/README.md).
- **Gentle-AI** configura el entorno de ingeniería de un agente de programación ya existente: flujos de trabajo, memoria y evidencia; no se presenta como un agente independiente que sustituye el entorno anfitrión. [Fuente: README de Gentle-AI](https://github.com/Gentleman-Programming/gentle-ai/blob/e8c9f5959cda64d64cb375de04fed524fef23d78/README.md).
- **gentle-shell** es un espacio de trabajo para agentes de programación específico de **Pi**, con agentes, tareas y cambios como áreas de atención; no es solamente un tema visual. Su vista **Changes** registra operaciones de escritura/edición realizadas con éxito mediante herramientas, pero no constituye una auditoría exhaustiva de Git. [Fuentes: README](https://github.com/Gentleman-Programming/gentle-shell/blob/4f5ab3973dccae74fc981531cd2e8ab8d3c6e8cf/README.md) y [documentación de gentle-shell](https://github.com/Gentleman-Programming/gentle-shell/blob/4f5ab3973dccae74fc981531cd2e8ab8d3c6e8cf/docs/gentle-shell.md).
- **Engram** es memoria persistente separada y agnóstica del agente: el agente selecciona qué guardar y puede buscar y recuperar registros después. Su implementación local utiliza un binario **Go** con **SQLite/FTS5**; ofrece interfaces **CLI, HTTP, MCP y TUI**. **Cloud** es replicación opcional; SQLite local sigue siendo la fuente de verdad. [Fuentes: README de Engram](https://github.com/Gentleman-Programming/engram/blob/9dad41baf01c6b9dacfd13808d614987c787ebc7/README.md) y [arquitectura](https://github.com/Gentleman-Programming/engram/blob/9dad41baf01c6b9dacfd13808d614987c787ebc7/docs/ARCHITECTURE.md).

## Pi y Gentle Shell en el showreel

- **Pi** se presenta como agente de programación minimalista y extensible para la terminal; su README instalado describe además plantillas, habilidades, extensiones, temas, paquetes y SDK. Estas son capacidades de **Pi**, no características que Gentle Shell invente. Fuente primaria consultada: README de `@earendil-works/pi-coding-agent` instalado localmente (ruta de instalación no portable); consultar [proyecto Pi](https://github.com/earendil-works/pi) antes de publicación.
- **Gentle Shell** se cuenta como espacio de trabajo específico de Pi: sesión con tareas, estado de ejecución y cambios capturados; agentes enfocados, dirigidos por la sesión principal, que regresan con resultados. Su vista Agents conserva hilos y puede mostrar información en vivo de modelo, tokens y tiempo transcurrido; el showreel omite cifras y nombres concretos. [Fuentes primarias: README oficial de Gentle Shell en `main`](https://github.com/Gentleman-Programming/gentle-shell/blob/main/README.md) y [guía oficial en `main`](https://github.com/Gentleman-Programming/gentle-shell/blob/main/docs/gentle-shell.md). `main` cambia: estos enlaces documentan la narrativa, no verifican una versión instalada o publicada.
- **Alcance de Changes:** captura llamadas exitosas de herramientas de escritura/edición de la sesión actual y sus agentes hijos propios; no registra escrituras de shell/editor ni constituye un inventario Git. En la pieza, afirmar positivamente «cambios de escritura y edición capturados», sin texto publicitario de descargo. La precisión de alcance queda aquí para edición/verificación interna. [Fuente: guía oficial de Gentle Shell, sección Changes](https://github.com/Gentleman-Programming/gentle-shell/blob/main/docs/gentle-shell.md).
- **ODD:** explorar antes de implementar, mantener ligera una petición pequeña y registrar trabajo sustancial autorizado. No atribuir memoria integrada a Gentle Shell: la memoria es opcional y proviene de una integración aparte. [Fuente: README oficial de Gentle Shell, sección ODD](https://github.com/Gentleman-Programming/gentle-shell/blob/main/README.md). El guion y las ventanas exactas están en [prompt del showreel](../prompts/gentle-shelll-ligero/showreel/prompt.md); EN/ES se entregan en SRT separados, sin quemarlos en pantalla.

## Flujos, no promesas universales

- **ODD (Organic Driven Development)** adapta el seguimiento al tamaño del trabajo: una petición pequeña permanece ligera; una implementación sustancial usa un documento de funcionalidades/tareas. [Fuente: uso de Gentle-AI](https://github.com/Gentleman-Programming/gentle-ai/blob/e8c9f5959cda64d64cb375de04fed524fef23d78/docs/usage.md).
- **RDD (Receipt-Driven Development)** habilita una revisión opcional y controlada por la persona usuaria de un candidato exacto e inmutable; su interruptor y consentimiento son propios del proceso de revisión. El resultado de la revisión no equivale a autorizar un commit ni una publicación: la entrega sigue la política ordinaria. [Fuente: integración de revisión de Gentle-AI](https://github.com/Gentleman-Programming/gentle-ai/blob/e8c9f5959cda64d64cb375de04fed524fef23d78/docs/review-integration.md).

## Uso responsable en medios

Describir las capacidades como dependientes del runtime y de su configuración: no prometer que todos los componentes estén disponibles en toda instalación, ni que estos tres productos se instalen juntos. Separar hechos documentados de interpretaciones visuales; no presentar el historial de **Changes** como historial completo del repositorio ni Cloud como requisito de Engram.
